Документація проекту: Застосунок для перегляду та фільтрації серіалів

Цей проект є веб-застосунком, який взаємодіє з публічним API TVMaze. Застосунок завантажує дані про серіали, відображає їх у вигляді карток, реалізує «розумну» пагінацію, динамічний пошук та сортування за назвою або рейтингом.

Структура проекту та ініціалізація

Код використовує суворий режим ("use strict") для підвищення безпеки та оптимізації роботи JavaScript. На початку файлу відбувається пошук основних HTML-елементів (контейнера для карток, інпуту пошуку, селекту сортування та блоку помилки). Одразу після цього через JS динамічно створюється та додається в DOM-дерево контейнер для пагінації (paginationContainer).

Для керування станом застосунку використовуються чотири глобальні змінні:

allShows: Масив-буфер, що зберігає початкові дані про всі серіали від API.

filteredShows: Робочий масив для відфільтрованих та відсортованих серіалів.

currentPage: Номер поточної активної сторінки (початково 1).

itemsPerPage: Кількість елементів на одній сторінці (дорівнює 12).

Повний опис функцій коду

Код складається з чотирьох взаємопов'язаних функцій, кожна з яких виконує свою роль:

Функція fetchShows (Завантаження даних)

Що робить: Асинхронно (async/await) надсилає запит до сервера.

Логіка: Якщо сервер відповідає успішно, дані записуються в allShows та filteredShows, після чого запускається процес обробки. Якщо мережа зникає або сервер видає помилку, блок try...catch ловить цей збій, очищує екран і показує користувачеві блок errorMessage із текстом про помилку.

Функція handleFilterAndSort (Обробка та фільтрація)

Що робить: Фільтрує та сортує масив даних перед виведенням на екран.

Логіка: Спочатку вона бере текст із пошуку, переводить його у нижній регістр і через метод filter залишає лише ті серіали, назва яких містить введені літери. Потім через метод sort сортує їх: або за рейтингом (від вищого до нижчого), або за назвою (за алфавітом через localeCompare). Після кожної такої дії вона примусово скидає currentPage на 1, щоб користувач бачив початок нового списку.

Функція renderShows (Відображення карток)

Що робить: Створює HTML-код для карток серіалів і вставляє його на сторінку.

Логіка: Спочатку очищує контейнер. Якщо після пошуку нічого не знайдено, вона виводить текст-попередження та прибирає кнопки пагінації. Якщо серіали є, вона за допомогою методу slice вирізає шматочок масиву (рівно 12 штук для поточної сторінки). За допомогою методу map створюється HTML-структура картки. Тут передбачено захист (fallback): якщо у серіалу немає картинки або рейтингу, код підставляє дефолтну заглушку. Наприкінці сформований HTML додається на сторінку та викликається створення кнопок пагінації.

Функція renderPagination (Керування сторінками)

Що робить: Створює кнопки « Назад », « Вперед » та інформацію про сторінки.

Логіка: Вираховує загальну кількість сторінок через округлення Math.ceil. Якщо сторінка лише одна, кнопки не створюються. Функція створює кнопку « Назад » (і блокує її на першій сторінці) та кнопку « Вперед » (і блокує її на останній сторінці). При натисканні на кнопки номер сторінки змінюється, серіали перемальовуються, а сторінка плавно прокручується вгору за допомогою window.scrollTo.

Слухачі подій (Евент-лістенери)

Наприкінці коду додано обробники подій:

На інпут пошуку повішено подію input, що запускає фільтрацію миттєво під час введення кожної літери.

На селект сортування повішено подію change, яка оновлює порядок карток одразу після зміни критерію сортування.

Останній рядок fetchShows() автоматично запускає всю систему під час першого відкриття сайту.

Опис HTML-структури (index.html)

HTML-файл визначає каркас сторінки та містить такі ключові елементи:

Метатеги: Тег viewport забезпечує коректне відображення сайту на мобільних телефонах (адаптивність).

Шапка сайту (header): Містить головний заголовок та блок controls, де розташовані поле для пошуку (searchInput) та випадаючий список для сортування (sortSelect).

Головний блок (main): Включає в себе прихований блок для помилок (error-message) та основний контейнер для карток (showsContainer).

Початковий стан: Всередині контейнера серіалів прописано текст "Завантаження даних...", який користувач бачить, поки JS робить запит до API. Потім цей текст автоматично стирається.

Підключення файлів: Стилі підключаються в тегу head через лінк на lb4.css, а логіка — в самому кінці тегу body через скрипт app.js, щоб код не блокував завантаження сторінки.

Опис стилізації (style.css / lb4.css)

CSS-файл відповідає за візуальний вигляд, сітку та інтерфейс користувача:

Загальні стилі (body): Встановлюють приємний для очей шрифт Arial, світло-сірий фон (#f5f5f5) та внутрішні відступи екрану.

Елементи керування (controls, input, select): Завдяки Flexbox (display: flex) інпут та селект вирівняні по центру з акуратними відступами (gap: 15px). Вони мають скруглені кути (border-radius: 5px) та збільшений шрифт для зручності кліків.

Адаптивна сітка (shows-grid): Це найважливіша частина. Використовується технологія CSS Grid. Рядок grid-template-columns: repeat(auto-fill, minmax(200px, 1fr)) автоматично розраховує кількість карток у рядку залежно від ширини екрану. Якщо екран великий — картки стають в ряд, якщо це смартфон — вони вибудовуються одна під одною без жодних медіа-запитів.

Картки фільмів (card): Кожна картка має білий фон, внутрішні відступи, скруглені кути та легку тінь (box-shadow) для створення ефекту об'єму. Картинки всередині звужуються під розмір картки завдяки max-width: 100%.

Службові класи (error, hidden): Клас error фарбує текст помилки в червоний колір і робить його жирним. Клас hidden має властивість display: none, що дозволяє JavaScript миттєво ховати або показувати елементи (наприклад, повідомлення про помилку чи кнопки пагінації).
